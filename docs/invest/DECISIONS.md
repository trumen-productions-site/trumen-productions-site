# Decisions — the investor page

Every choice the build made that `HANDOFF.md` did not dictate, or where it departed from the brief, with the
reason. Numbered so a review can cite them. Newest at the bottom.

| # | Decision | Reason |
|---|---|---|
| D-01 | **Built inside this repository's zero-dependency toolchain** (`build.mjs`, template-literal pages, `node:test`) rather than scaffolding Astro + Tailwind + Preact as § 6 lists. | The brief's own rule — "keep the adapter boundaries and swap the vendor; do not restructure the app" — read against a repository that already *is* the app: locked brand tokens, 548 passing assertions, a documented editing workflow, and three deploy targets. A second framework would have meant two build systems, two test harnesses and a palette that could drift. Every contract in the brief (typed config, Pending tokens, gates, footnote engine, lints, flow machine, D1 schema, adapters) is implemented; only the framework is different. |
| D-02 | The flow island is a **vanilla ES-module state machine** (`src/assets/js/invest/machine.js`), not Preact. | The machine is 150 lines and pure; the renderer is DOM. The same file runs in the Node tests (FLOW-01) and in the browser, so what is proved is what runs. Total JS on the page is 50 KB transferred, under the 60 KB budget, with no framework to update. |
| D-03 | **Plain JavaScript with JSDoc** and a 120-line schema validator (`src/invest/lib/schema.mjs`) instead of TypeScript strict and zod. | The repository has no compile step and no dependencies by design. The validator does the one job needed — refuse a wrong-shaped term and say where — and is itself tested. |
| D-04 | **The day counts — decided.** The brief phrases the detention as "seventy-seven days past the Court's order". The page leads with the over-detention — *ninety-three days* from the order of March 27, 2000 to the remittitur of June 28, 2000 — and states *seventy-seven days* as the span between the two filings of the opinion (March 27 → June 12). | Two sources disagreed; the later and better-evidenced one governs. This repository's record was locked by Michael on September 5, 2026 (`four-rules-reels/src/canon.py`, `site.config.mjs → facts`), derives both numbers from dated documents in the case file, and is enforced by the existing tests, which refuse "seventy-seven days past". The Drive documents of September 29 and October 3 carry "seventy-seven days" as a canon figure without naming its span — the pre-lock formulation surviving in a canon sheet. Both numbers are correct for what each one is, so the page states both; it leads with the one that describes what was done to a person. The counsel packet records the reconciliation as information. If Michael wants the page to lead with seventy-seven instead, it is one line in `config/story.mjs`. |
| D-05 | The `<title>` is `Invest in CLEARLY ESTABLISHED · TruMen Productions`, with the plain spelling, not the star glyph the brief gives. | `test/html.test.mjs` requires the plain company name in every title and documents why: in a tab or a search result the star renders as mojibake on some systems. The page is `noindex`, so the title is only ever seen in a tab. Visible copy uses the glyph everywhere. |
| D-06 | **Comparables are off** (`features.comps = false`). Five honest candidates are in `config/comps.mjs → candidates` with the figure each must be checked against; none renders. | § 9.7 requires a live `sourceUrl` and a `verifiedOn` date for every comparable. Outbound HTTPS to Box Office Mojo was refused from the build environment, so no figure could be verified. `npm run check:sources` is the worksheet; a human confirms the figures, adds the date, moves the entry into `comps`, and the section turns on at three. Nothing unverified is published. |
| D-07 | **The Cal.com adapter is written but unverified** against current documentation. | api.cal.com and the Cal.com docs were unreachable from the build environment; the brief says not to rely on memory for endpoints, so the adapter is isolated behind `SchedulerAdapter`, tested against a fake, and marked. Phase 4 acceptance — a real test booking landing on the host's calendar from staging — is the check, and the `MockAdapter` runs the whole flow until then. |
| D-08 | **No-JavaScript fallback without Turnstile.** The plain form cannot carry a Turnstile token (Turnstile needs script), so it is protected by a honeypot field and a limit of three posts per hour per address, saved on a separate `nojs` channel, and lands on `/invest/received/` (or `/invest/not-accredited/`). | The brief requires both "rejects missing Turnstile" (API-01) and "JavaScript disabled: fallback form posts and saves a lead" (E2E-03). The two are reconciled by channel: the island must present a token; the form must pass the honeypot and the tighter limit, and its leads are labelled so the producer knows no call was booked. |
| D-09 | The 30-minute **"lead without booking" notice** is an authenticated endpoint (`GET /api/cron/abandoned`, `CRON_SECRET`) that a Worker cron trigger or any external scheduler calls. | Pages Functions have no scheduler of their own. The endpoint is idempotent (one notice per lead) and tested. |
| D-10 | **Rate limiting lives in D1** (`ratelimit` table, fixed window) rather than KV or the Workers rate-limit binding. | One store, portable to the local SQLite shim, tested with the same migration. Fine at this page's scale; a binding can replace it behind the same function if traffic ever warrants. |
| D-11 | **A not-accredited answer stores no personal data.** The island never posts it; the plain form's post is acknowledged and discarded; only an anonymous `not_accredited_end` event is logged. | § 10: a respectful end screen with no offering details and no upsell. Holding the name and phone number of someone we may not talk to about the offering serves no purpose and is one more record to protect. |
| D-12 | **Brand colours are the repository's locked tokens** (`#0b1f3a`, `#f3ebdd`, `#b08d57`, `#2e6b4f`, `#d4af37`), not the brief's placeholders (`#0E1B2E` …). | The brief says to sample the exact values from the letterhead and deck assets "until then use placeholders". This repository locked those values on July 12, 2026 and tests them against the reel pipeline's `tokens.json`. Brass on cream is 2.6:1, so small brass-coloured text on light grounds uses `--brass-deep` (5.8:1), as the site already does. |
| D-13 | **The investor pages ship dark in three ways**: `noindex, nofollow` on every page and an `X-Robots-Tag` header; no link from the company site (tested); and a `--site-only` build that leaves them out entirely, which is what Netlify and GitHub Pages publish. They deploy only through `invest-deploy.yml` to a Cloudflare Pages project behind Access. | The brief's first rule. Without the site-only build, the company site's own deploy would have put the staging page on a public URL. |
| D-14 | **SNAP-01** asserts layout at 375/768/1280 on every machine (no horizontal overflow, section order, hero two-column vs. stacked, stat-grid rows, headline within its container, sticky bar hidden on load) and compares full-page screenshots to committed baselines with an in-browser pixel diff (2% threshold) only when the running machine's measured font fingerprint matches the baseline's; otherwise the comparison is reported as skipped. `npm run test:e2e:update` rewrites the baselines and their fingerprints. | The first CI run showed ~14% drift with changed page heights — the runner's serif fallback is not the authoring machine's. A pixel diff across font stacks measures the fonts, not the page; the layout assertions measure the page. No image-diff dependency; images are kept as CI artefacts either way. |
| D-15 | **PERF-01** runs Lighthouse against the local dev server (`tools/dev-api.mjs`) rather than a deployed URL. | Budgets are checked on every CI run before anything deploys. The numbers from a real edge deployment can only be better. |
| D-16 | **Node ≥ 22.13**, up from 20. | The API tests run the real migration on `node:sqlite` through a D1-shaped shim, so the SQL that is tested is the SQL that runs. The build itself still needs nothing installed. |
| D-17 | `/privacy/` and `/terms/` are at the root, as the brief specifies, flagged `invest: true` and `noindex`. | They belong to the investor page and ship with it. `/terms/` is only linked when `features.sms` is on. |
| D-18 | When the minimum is pending, step 2 offers one option — "I'd rather discuss the amount on the call" — and says the minimum is not yet set. | Ranges are generated from the minimum (§ 10); inventing them would invent a number. |
| D-19 | Email is **text-first** through a `Resend` adapter, with a logging adapter when no key is set. The investor's confirmation never carries the amount range or the accredited answer. | § 6 and § 12. The producer's notices carry both. |
| D-20 | The **consent banner and Meta pixel code paths exist but are inert**: `features.metaPixel = false`, the CSP admits no Meta host until the flag is on, and the Conversions API sends only `Lead` and `Schedule` with hashed email and phone. | § 12, verbatim. |
| D-21 | The **investor pages load no web font**. The company site loads Poppins for its wordmark; the investor pages set `fonts: false` and let the system sans carry the small wordmark in the header and footer. | § 15: "no web-font downloads". It also removed a render-blocking request from the critical path; LCP is measured in `npm run perf`. |
| D-22 | The island's three imports are declared with `<link rel="modulepreload">`. | Without it the browser discovers `machine.js`, `validators.js` and `utm.js` only after `flow.js` arrives — a second round trip on a 4G connection. |
| D-23 | Proper names supplied by config (the issuer's legal name, the booking host) are **allowed by the name lint automatically**. | A decision landing in config should not require editing the lint's allowlist; anything else that is capitalised still does. |
| D-24 | Staging ribbon text is "Staging — not an offering · build _sha_ · _n_ of _m_ launch gates unsigned". | The brief asks for a red "STAGING — NOT AN OFFERING" ribbon; the build id and the gate count make a screenshot self-describing in a review thread. |
